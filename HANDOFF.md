# AeroLake handoff guide

This is the operational handoff for the next owner of AeroLake. The detailed technical narrative is in [docs/handoff-document.md](docs/handoff-document.md); the operator and command references are [docs/operator-cli-guide.md](docs/operator-cli-guide.md) and [docs/cli-reference.md](docs/cli-reference.md).

## What is deployed

```text
Acquisition station -> AeroLake -> MinIO/S3 (source of truth)
                                      |
                                      +-> IQEngine datasource -> catalog, query UI, analysis
```

Each capture is a SigMF pair, `capture.sigmf-data` plus `capture.sigmf-meta`. The object store remains authoritative. IQEngine indexes that metadata and exposes search/analysis; it is not a second store and AeroLake must never access IQEngine's MongoDB directly.

Optional IQEngine sidecars (`.jpg`, `.preview.jpg`, `.minimap`) are generated by AeroLake with `--iqengine` or `aerolake-iqengine-artifacts`. The Streamlit capture GUI may also write a separate `-preview.png` convenience image.

## First actions for the new owner

1. Transfer the repository from the personal GitHub account to the laboratory GitLab and give at least two lab members maintainer access.
2. Move MinIO/S3 credentials and the bucket to an administered lab service. Create a least-privilege AeroLake service account for `aerolake-captures`.
3. Configure an IQEngine datasource that points to the same bucket and prefix. Give AeroLake a dedicated IQEngine integration API identity, not database credentials.
4. Put endpoint and credentials in the deployment secret store or local `.env`; do not commit them.
5. Prove the chain with `aerolake-healthcheck`, a small ingest, an IQEngine sync, an IQEngine CLI query, and a browser search.

## Configure a station

Install Python/uv, Git, and—on an SDR station—SoapySDR and the device driver. On Windows use WSL2 and `usbipd-win` for USB SDRs.

```bash
git clone <repository-url>
cd aerolake
cp .env.example .env
uv sync
bash setup-soapy.sh             # SDR stations; run again after uv sync
```

Configure the required storage values:

```dotenv
AEROLAKE_S3_ENDPOINT=https://<minio-api-host>
AEROLAKE_S3_ACCESS_KEY=<service-account-key>
AEROLAKE_S3_SECRET_KEY=<service-account-secret>
AEROLAKE_S3_BUCKET=aerolake-captures
```

For IQEngine discovery, also configure:

```dotenv
AEROLAKE_IQENGINE_URL=https://<iqengine-host>
AEROLAKE_IQENGINE_TOKEN=<dedicated-service-token>
AEROLAKE_IQENGINE_ACCOUNT=<datasource-account>
AEROLAKE_IQENGINE_CONTAINER=<datasource-container>
# AEROLAKE_IQENGINE_PREFIX=<optional-prefix>
```

Use `AEROLAKE_S3_CA_BUNDLE` for an internal CA. `AEROLAKE_S3_VERIFY_SSL=false` is only a temporary trusted-network workaround.

## Day-to-day operations

```bash
uv run aerolake-healthcheck
uv run aerolake-capture --config examples/capture.example.toml
uv run aerolake-ingest capture.sigmf-data --iqengine
uv run aerolake-list --catalog minio --signal-type gnss_l1
uv run aerolake-list --catalog iqengine --signal-type iridium --json
```

For a raw file without metadata, provide `--signal-type`, `--sample-rate`, and `--center-freq`. AeroLake writes a metadata template and stops; complete every `<missing:...>` value, then rerun without metadata flags. Existing pairs need `global.aerolake:signal_type`, valid sample alignment, and a non-empty annotation list. AeroLake verifies or adds the data hash before upload.

After an external upload or changed metadata, request a catalog sync with `bash init-sync.sh` (Linux/WSL) or `init-sync.bat` (Windows), then query using `--catalog iqengine`. `--catalog auto` is suitable for normal use but may fall back to MinIO; it is not a test that IQEngine is working.

Use `aerolake-iqengine-artifacts <base> --upload --key-prefix <prefix>` to add sidecars to an existing local pair. See the CLI reference for safe cancellation, Iridium annotations, collections, replay, and ZeroMQ streaming.

## Ownership boundaries

| Component | Owner / source of truth |
|---|---|
| SigMF data, metadata, object lifecycle, direct replay | AeroLake + MinIO/S3 |
| Datasource configuration, indexing, search UI/API | IQEngine |
| MongoDB schema, collections, and credentials | IQEngine only |
| RF transmit/re-emission | Separate future work; see ADR-019 |

The implemented catalog query layer is IQEngine. Apache Iceberg/SQL remains a possible future analytical layer, not a prerequisite for capture discovery.

## Verification and maintenance

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest
```

Keep `.env` and service secrets out of Git. Re-run `setup-soapy.sh` after every `uv sync` on SDR stations. Use the documented IQEngine integration routes only; the relevant design decisions are ADR-021 through ADR-024.
